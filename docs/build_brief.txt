# Build Brief: `mjplay` — Browser MJCF/URDF Viewer + Contact Playground

**One-liner:** Load a robot model in the browser, drag its joints, watch contacts light up red in real time. `urdfcheck` with a face.

**Completion gate (memorize this, it's the whole point):**
> *Load a Menagerie robot, drag a joint slider, and when two bodies collide the contacting geometry turns red — running at 60fps in the browser with a reset button.*

If it does that, it's done. Everything below the gate is explicitly out of scope.

## Why this one is tractable now
The two historical time-sinks are both gone: MuJoCo now ships an official, macOS-tested WASM build via `@mujoco/mujoco`, and `zalo/mujoco_wasm` gives you a working MuJoCo+Three.js example harness to fork. Your remaining work is the *interaction layer* — sliders, contact-reading, red highlighting — not the physics or the compile.

## Stack
- **Physics:** `@mujoco/mujoco` (official npm WASM build). Fallback: fork `zalo/mujoco_wasm` if you want the Three.js glue pre-wired.
- **Render:** Three.js (matches zalo's example, minimizes glue you write).
- **Build:** Vite. Serve over HTTP (WASM needs it — no `file://`).
- **Models:** MuJoCo Menagerie (Franka Panda, Unitree Go2, etc. — clean MJCF, no conversion risk). This sidesteps the URDF-fidelity problem entirely for your demo models.

## The one technical thing to de-risk first (M0)
Contact reading is the load-bearing feature. After `mj_step`, MuJoCo populates `data.contact` (an array of contact structs) and `data.ncon` (count). Each contact references two geom IDs (`geom1`, `geom2`). **Before writing any UI**, prove you can read `data.ncon` and pull geom IDs from the WASM bindings in a `console.log`. If contacts aren't cleanly exposed through the JS API, the whole "red on contact" premise wobbles and you want to know on day one, not day five. This is your go/no-go probe.

(The official bindings wrap the C API with typed-array buffers for `qpos`, `xpos`, etc., so contact arrays are very likely exposed — but *verify*, don't assume. That's exactly the kind of assumption that eats a weekend.)

## Milestones — each independently demoable

**M0 — Contact probe + viewer boots (go/no-go)**
Load a Menagerie MJCF, render it in Three.js, step the sim, and `console.log(data.ncon)` with geom IDs when you manually drop the robot onto the floor. No UI yet. Gate: *numbers print when things touch.* If this works, the project is real.

**M1 — Joint dragging**
Auto-generate a slider per actuated joint from `model.njnt` / joint ranges. Slider writes to `data.qpos` (or `data.ctrl`), call `mj_forward`, mesh updates. Gate: *drag slider, robot moves.* This alone is already a useful `urdfcheck`-style tool — shippable stopping point.

**M2 — Red on contact (the money shot)**
Each frame: read `data.contact[0..ncon]`, map contacting geom IDs → Three.js meshes, swap their material to red (revert when contact clears). Gate: *the completion-gate sentence above.* Ship it.
